# تشغيل بيتي ومشاركته من ملف CMD

**تحديث 2026-11-15:** تم ربط Worker ثابت للمشروع: https://myhome.mohamed-fooda-mtf.workers.dev. بعد الربط الأول يحدّثه `Start_MyHome.cmd` تلقائيًا، ويُحفظ رابط المشاركة النهائي في `artifacts/project-url.txt`؛ يبقى `share-url.txt` عنوان النفق المؤقت فقط. الـWeb والـAPI وقاعدة البيانات محلية، لذلك يظل الكمبيوتر وDocker شغّالين. APK المبني بعنوان الـWorker لا يحتاج إعادة بناء لمجرد تغير النفق. [إعداد الربط وإعادة النشر والحدود](38_CLOUDFLARE_WORKER.md). التفاصيل السابقة أدناه تصف التشغيل العام بالنفق قبل ربط الـWorker وتبقى كتاريخ.

من فولدر المشروع، افتح **`Start_MyHome.cmd`** بدبل كليك. لا يحتاج تشغيل CMD كمسؤول.

الملف يشغّل Docker Desktop لو متوقف، ثم PostgreSQL والـBackend لقاعدة **`myhome_demo`** المنفصلة، ويبني نسخة Web عند الحاجة. في النهاية يعرض ويفتح رابط **HTTPS** يمكن فتحه من متصفح الموبايل أو إرساله لمجرّب من خارج شبكة الواي فاي.

المتطلبات: Windows، Docker Desktop بوضع Linux containers، Flutter وPython 3.11+ في PATH، وإنترنت. أول تشغيل قد يستغرق عدة دقائق لتنزيل صور Docker وتجهيز Python وبناء Flutter. تشغيلات لاحقة تستخدم الصور والبناء المحفوظ إذا لم يتغير الكود أو إصدار Flutter.

## الاستخدام

```cmd
Start_MyHome.cmd
```

- `MOBILE / SHARE`: رابط HTTPS للموبايل ولأي شخص تريد أن يجرب الويب.
- `THIS COMPUTER`: `http://localhost:8082` للتجربة من الكمبيوتر نفسه.
- آخر رابط مشاركة محفوظ محليًا في `artifacts/share-url.txt`.
- حسابات التجربة وكلمات مرورها العشوائية في `artifacts/demo-accounts.json`. أرسل للمجرّب حساب مستخدم عادي مناسب؛ لا تنشر ملف الحسابات أو حساب الإدارة.
- يمكن للمجرّب إنشاء حساب عادي جديد أيضًا. إعدادات الإدارة والمستندات تظل محمية بصلاحيات الـBackend.
- يظل الكمبيوتر وDocker متصلين بالإنترنت أثناء التجربة. إغلاق نافذة CMD لا يوقف حاويات Docker.

لإيقاف المشاركة والـDemo افتح:

```cmd
Stop_MyHome.cmd
```

هذا يوقف النفق والويب وDemo API دون حذف قاعدة البيانات أو الـvolumes. PostgreSQL يظل يعمل لأنه قد يخدم أيضًا API التطبيق الأساسية.

## تجربة تطبيق أندرويد نفسه

إذا أردت ملف APK متصلًا بالسيرفر الحالي، افتح CMD داخل فولدر المشروع واكتب:

```cmd
Start_MyHome.cmd -Android
```

يشغّل نفس الرابط ثم يبني **Android debug APK** في `artifacts/MyHome-demo.apk`. انقل هذا الملف لهاتف أندرويد وثبّته للتجربة. يحتاج Android SDK على الكمبيوتر. إذا تغير رابط المشاركة بعد إعادة تشغيل النفق، أعد الأمر لبناء APK بالرابط الجديد؛ النسخة القديمة تحتفظ بعنوان الـAPI الذي بُنيت عليه. هذه نسخة تجربة وليست نسخة متجر موقّعة للإنتاج. iPhone يمكنه تجربة رابط الويب؛ بناء iOS يحتاج macOS/Xcode.

## اختيارات إضافية

```cmd
Start_MyHome.cmd -Local
Start_MyHome.cmd -Rebuild
Start_MyHome.cmd -NoBrowser
```

- `-Local`: الكمبيوتر فقط، دون نفق خارجي؛ يوقف أي نفق مشاركة قائم. يستخدم localhost، ولا ينشئ رابط HTTP للشبكة المحلية يصلح لتسجيل الدخول من الهاتف.
- `-Rebuild`: يجبر إعادة بناء الويب حتى لو لم يتغير الكود.
- `-NoBrowser`: يعرض الروابط دون فتح المتصفح تلقائيًا.
- يمكن جمع الاختيارات المناسبة، مثل `-Android -NoBrowser`. `-Android` يحتاج وضع HTTPS ولا يجتمع مع `-Local`.

## التصميم وحفظ البيانات

- Caddy يقدم ملفات Web المبنية فقط من `artifacts/share-web`، ويوجه `/api/v1/*` إلى **Demo API**. لا يصل النفق إلى قاعدة التطبيق الأساسية أو PostgreSQL مباشرة، ولا تُركّب ملفات الحسابات أو `.env` أو المستندات الخاصة في خادم الملفات.
- Flutter يُبنى بـ`API_BASE_URL=/api/v1` ويحوّله على الويب إلى عنوان نفس النطاق الحالي؛ بذلك لا يحاول هاتف المجرّب الاتصال بـlocalhost الخاص به، ولا تظهر مشكلة HTTPS مع API تعمل بـHTTP على منفذ آخر.
- استخدام HTTPS ضروري لتخزين جلسات الدخول بأمان في المتصفح؛ [المكتبة الرسمية توضح اشتراط HTTPS أو localhost](https://pub.dev/packages/flutter_secure_storage).
- الرابط مؤقت من [Cloudflare Quick Tunnels](https://developers.cloudflare.com/tunnel/get-started/quick-tunnels/)، دون حساب أو دومين. قد يتغير عند إعادة تشغيل النفق، وهو متاح لأي شخص يمتلكه. هذه مشاركة للتجربة وليست استضافة إنتاج دائمة.
- التشغيل اليومي يستخدم `start_demo.ps1 -SeedIfEmpty`: يجهز الحسابات الاصطناعية فقط إن لم تكن موجودة، ثم يحتفظ بتعديلاتك وأدوارك وإعلاناتك. تشغيل `tools/start_demo.ps1` وحده دون هذا الاختيار يبقي سلوك فحص السيناريو الأصلي الموثق؛ استخدم ملف CMD للتجربة اليومية.
- ملفات CMD تحل مسار المشروع تلقائيًا، بما في ذلك المسافات في `Flutter apps`. لا تحتاج لتعديل IP أو راوتر أو قواعد Windows Firewall.

## عند وجود مشكلة

- راجع `artifacts/launcher.log`؛ لا ترسل ملف `.env` أو بيانات الحسابات عند مشاركة الخطأ.
- إذا لم يبدأ Docker، افتحه وانتظر جاهزية Linux engine ثم أعد تشغيل الملف.
- إذا فشل إنشاء النفق، جرّب اتصال الإنترنت أو VPN/سياسة الشبكة، أو استخدم `-Local` مؤقتًا للكمبيوتر. لا حاجة لتنزيل cloudflared يدويًا؛ يعمل داخل Docker.
- إذا كان المنفذ 8082 مشغولًا، أوقف خادمك الآخر أو حاوية قديمة تخصه ثم أعد التشغيل. الملف لا يقتل عمليات أخرى تلقائيًا.
- عند تغيير نسخة Flutter أو ملفات التطبيق يعاد البناء تلقائيًا؛ استخدم `-Rebuild` لو احتجت بناءً جديدًا يدويًا.
